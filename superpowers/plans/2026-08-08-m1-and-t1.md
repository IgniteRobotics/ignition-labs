# M1 Java Fundamentals + T1 Find-the-Bug Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `projects/m1-java-fundamentals/` (six L3 stub exercises with complete given tests, a compiler-error garden, and a blocking-wait demo) and `projects/testouts/t1-find-the-bug/` (three rotating bug variants), so a Track A student can work M1 end to end and a Track B/C/D student can test out of it.

**Architecture:** Two standalone GradleRIO projects, siblings under `projects/`, each with its own wrapper and `settings.gradle` (spec §4.2). M1 is L3 scaffold-fade: every class ships with a signature and a Javadoc contract and a body that throws `UnsupportedOperationException`; every test ships complete and read-only. T1 is the inverse: three working methods with planted bugs and tests that fail because of them. Both satisfy the same CI invariant — `assemble` green, `test` red, on an unmodified clone.

**Tech Stack:** Java 17, GradleRIO 2026.2.1, Gradle 8.11, Spotless 8.2.1 (`googleJavaFormat 1.19.2`), JUnit Jupiter 5.10.1. No vendordeps in either project — M1 is plain Java (spec §9.2).

## Global Constraints

Every task's requirements implicitly include this section.

- **Java toolchain.** Local Gradle runs need `export JAVA_HOME=~/wpilib/2026/jdk`. Without it the wrapper picks up a Java 11 JVM and both plugins fail to resolve with "Dependency requires at least JVM runtime version 17." This is an environment fact, not a build defect — do not "fix" `build.gradle` in response to it.
- **Versions are fixed** (spec §4.3): GradleRIO `2026.2.1`, Gradle wrapper `8.11`, `sourceCompatibility`/`targetCompatibility` 17, Spotless plugin `8.2.1`, `googleJavaFormat('1.19.2').reflowLongStrings()`, JUnit `org.junit.jupiter:junit-jupiter:5.10.1`. Never bump a version as part of this plan.
- **`enforceCheck false`, and never `compileJava.dependsOn 'spotlessApply'`** (spec §4.3). Auto-apply-on-compile and a real CI format check are mutually exclusive; wiring it back is the exact defect that made M0's gate unreachable.
- **Package naming** (spec §4.4): M1 sources live in `frc.training.m1`. T1 sources live in `frc.testout.t1`. Never `frc.robot` — these are pure exercises with no robot, and naming them `frc.robot` invites pasting training code into a season repo out of muscle memory.
- **Vendordeps: none** in either project (spec §9.2). No `vendordeps/` directory at all.
- **A stub never contains the answer in a comment** (spec §8). `// TODO: divide by ticksPerRotation` is the solution with extra steps. The Javadoc states the *contract* — inputs, outputs, edge cases — never the implementation. This applies to Javadoc, inline comments, README text, and variable names.
- **A given test never asserts on implementation** (spec §8). It asserts on behavior through the public API.
- **Every skeleton compiles on a clean clone** (spec §12.3). Stubs throw `UnsupportedOperationException`; they never fail to compile. `./gradlew assemble` must be green and `./gradlew test` must be red, in that order.
- **No test may assert that the stub throws.** A test asserting `UnsupportedOperationException` passes against the unmodified skeleton, which inverts the whole gate. If such a test exists, `skeleton-integrity.yml`'s inverted check still fails the build only if *some other* test fails — it is not a safe pattern. Never write one.
- **Double assertions always use the delta overload:** `assertEquals(expected, actual, 1e-9)`. M1 teaches that `==` is wrong for doubles; the given tests must model the lesson they teach.
- **Committed Java must already be `googleJavaFormat` clean.** `skeleton-integrity.yml` exempts exactly one filename by convention — `FormatMe.java`, M0's formatting exercise — and nothing in M1 or T1 is named that. Every task that adds Java ends by running `./gradlew spotlessApply` and committing the result.
- **No pre-2026 Ignite references** (spec §12.1). No student-facing path may point at `2025-Robotics-Intro`, `Robot-2025`, or earlier.
- **T1's README must never say which variant carries which bug.** The three bug *categories* are already public in `docs/programming/milestones/m1-java-fundamentals.md`; the mapping is the answer, and it lives only in the private solutions repository (spec §11.1).

**Why one T1 project and not three.** The spec calls T1 "three rotating variants — mentor picks one." Three sibling Gradle projects would triple the wrapper, the CI matrix entry, and the maintenance, and `skeleton-integrity.yml`'s matrix (`find projects -mindepth 2 -maxdepth 3 -name settings.gradle`) would not even reach a fourth level of nesting. One project with three sibling classes gets the same rotation for a third of the cost. A student who sees all three broken methods learns nothing about the fix for theirs — the leak the spec guards against is one student *telling* the next, and mentor choice among three is what defeats that.

package frc.training.m1;

/**
 * Shows what waiting does to a robot.
 *
 * <p>Run it with {@code ./gradlew blockingWaitDemo}.
 *
 * <p>Robot code runs one loop every 20 milliseconds, and everything happens inside that loop:
 * reading the driver's sticks, checking limit switches, deciding whether to stop. This program
 * stands in for that loop. On iteration 10 it does the thing that feels natural and is wrong — it
 * waits for something to be ready instead of checking whether it is ready and coming back next
 * time.
 *
 * <p>Watch the timestamps.
 */
public final class BlockingWaitDemo {

  private static final int LOOP_PERIOD_MS = 20;
  private static final int ITERATIONS = 20;
  private static final int STALL_AT_ITERATION = 10;
  private static final long STALL_MS = 2000;

  private BlockingWaitDemo() {}

  /**
   * Runs the demonstration.
   *
   * @param args ignored
   * @throws InterruptedException if the sleep between loops is interrupted
   */
  public static void main(String[] args) throws InterruptedException {
    long start = System.currentTimeMillis();

    for (int i = 0; i < ITERATIONS; i++) {
      if (i == STALL_AT_ITERATION) {
        waitUntilReady();
      }
      System.out.printf("loop %2d  at %6d ms%n", i, System.currentTimeMillis() - start);
      Thread.sleep(LOOP_PERIOD_MS);
    }

    System.out.println();
    System.out.printf(
        "Loops 0-%d each came round about every %d ms.%n",
        STALL_AT_ITERATION - 1, LOOP_PERIOD_MS);
    System.out.printf(
        "Loop %d did not. For %d ms this robot read no sticks, checked no limit switches, and"
            + " could not be told to stop.%n",
        STALL_AT_ITERATION, STALL_MS);
    System.out.println(
        "On a field, that is a robot still driving at whatever it was last told, into whatever is"
            + " in front of it.");
  }

  /** The mistake: waiting for a condition instead of checking it and returning. */
  private static void waitUntilReady() {
    long deadline = System.currentTimeMillis() + STALL_MS;
    while (System.currentTimeMillis() < deadline) {
      // Deliberately spinning. This is the bug being demonstrated.
    }
  }
}

/** Test-out variant A. */
public final class VariantA {

  private VariantA() {}

  /**
   * Averages the first {@code count} samples in a rolling sensor buffer.
   *
   * @param samples the buffer to read from
   * @param count how many leading samples to average, at least 1 and at most
   *     {@code samples.length}
   * @return the mean of those samples

  public static double meanOfFirst(double[] samples, int count) {

    for (int i = 0; i <= count; i++) {

    }
    return total / count;
  }
}
